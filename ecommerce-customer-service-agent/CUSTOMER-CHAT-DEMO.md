# 面向客户的智能客服 Demo

这个版本重点解决两类真实客服问题：

1. 用户可能用任意网络用语、热梗或不完整口语开场，不能依赖固定关键词表。
2. 闲聊、店铺规则、实时查询和高风险投诉必须进入不同处理路径。

## 路径分工

```text
用户消息
  ├─ 投诉/差评/人工诉求 -> 人工转接
  ├─ 订单/物流/库存/退款实时查询 -> 受控 Tool -> 模拟业务 API
  ├─ 发货/退换货等通用规则 -> RAG/本地知识检索
  └─ 问候/网络用语/一般闲聊 -> 无 Tool 权限的会话模型
```

会话模型只能负责自然交流，不能调用业务 Tool，也不能编造订单、物流、
库存或退款结果。实时数据只能由白名单 Tool 查询；业务 API 负责订单归属
校验，失败后继续保留原查询意图，用户可以直接补充新的订单号。

## 运行方式

复制 `.env.example` 为 `.env`，填写本地模型配置。密钥文件已被
`.gitignore` 排除，不能提交到仓库。

先启动模拟业务 API：

```powershell
python mock_business_api.py
```

再启动客户聊天页面：

```powershell
python customer_chat.py
```

默认访问地址：`http://127.0.0.1:5058/`

## 建议演示脚本

开放式会话：

```text
用户：阁下又该如何应对
客服：根据语义自然承接，不依赖问候词表。
```

店铺规则：

```text
用户：你们什么时候发货？
客服：常规现货商品一般在付款后48小时内发货；预售商品按页面标注时间发货。
```

连续订单查询：

```text
用户：我的订单发货了吗？
客服：追问订单号。
用户：DD1002
客服：身份校验失败，并继续等待正确订单号。
用户：DD8898
客服：订单不存在，并继续等待正确订单号。
用户：DD1001
客服：返回模拟订单状态。
```

## 验收

```powershell
python -m unittest discover -s tests -v
```

当前覆盖开放式会话分流、店铺规则与实时订单边界、订单归属校验、
失败后的任务上下文恢复、Tool 白名单和知识检索降级。

## 真实性说明

- 项目是个人业务原型，订单与客户数据均为模拟数据。
- 未接入抖店正式 API，未在企业生产环境上线。
- 模型与向量服务异常时会安全降级，不会把内部报错或知识库字段直接展示给客户。
